# October 31 Zenoh bridge

The browser exports oracle occupancy for `oct-31-testing`. A separate Python
program in the orchestrator checkout maps that run's topics to the existing
A* and pure-pursuit Zenoh keys. JavaScript owns all simulation and occupancy.

## Start a run

In the orchestrator checkout, install the tested Python dependencies:

```bash
python -m pip install eclipse-zenoh==1.10.1 websockets==16.0
```

1. Start the updated orchestrator with `python main.py`.
2. Open the simulator with `oct-31-testing` selected. Wait for its
   orchestrator connection and message-schema registration.
3. Start the adapter in the orchestrator checkout with
   `python client/oct31_zenoh_bridge.py`. Wait for `Transport ready`.
4. Start the existing `a_star` and `pure_pursuit` programs on the same host.
5. Start the browser episode.

The adapter defaults to `--orch-ws ws://localhost:8080` and
`--types-api http://localhost:8090`. It opens a native Zenoh peer session;
there is no remote API daemon or Node Zenoh dependency. Its startup snapshot
supports joining a running episode. Resending the cached goal with every grid
supports starting A* later.

Use one active browser run. Restart the adapter and Rust consumers between
episodes or scenario changes. A WebSocket disconnection ends the adapter;
restart it manually. Ctrl-C closes its transports and prints traffic totals.

## Wire contract

| Orchestrator | Zenoh | Payload |
| --- | --- | --- |
| `/tf`, `odom` to `base_link` | `cev/localization/pose` | JSON `location.x`, `location.y`, `heading` (radians) |
| `/goal` | `cev/commands/goal` | JSON `longitude` = x, `latitude` = y, both **meters** |
| `/planning/costmap` | `cev/perception/costmap_raw` | 32-byte header, then row-major 0/255 cells |
| `/controls/command` (adapter output) | `cev/commands/control` (adapter input) | Stamped SI Ackermann from JSON speed and steering, positive left |

The browser publishes `/planning/costmap` as a `std_msgs/String` JSON value
with `rows`, `cols`, `resolution`, `origin_x`, `origin_y`, and base64 `cells`.
The grid is 1000 by 1000 at 0.05 m, sampled every 500,000,000 simulation ns
after motion. Rows are reversed from world Z into REP-103 Y; `origin_x` is
the sample's `originX`, and `origin_y = -(originZ + rows * resolution)`.
Free cells are 0 and blocked cells are 255. Other actors and episode-overlay
obstacles are included; ego is not stamped.

The adapter packs `<QIIfffI`: zero timestamp, cols, rows, resolution, origin
x/y, and zero reserved. It uses the latest matching TF stamp, increasing
sequence, `mode: "velocity"`, and `deadline_ns: 0` on controls.

The orchestrator server must accept 8 MiB messages. The adapter accepts up to
64 MiB for snapshots. The approximately 1.33 MB grid exceeds the old 1 MiB
server default even at a low publish rate. Closed sockets and backpressure
drop browser exports without stopping simulation.

## Authority and boundaries

This is a transport test. `authority: reference` stays selected and the
scenario follower continues driving at its configured 2 m/s. Observing a
command on `/controls/command` does not show that pursuit controls the car.
No manifest, observation-profile, Protobuf, world, or episode hash changes
are required. Other browser manifests and all headless runs leave this
demo-only export inactive.

- All 20 focused simulator goal/occupancy/export tests passed. Lint passed
  with three existing React hook warnings. The full Node suite reported

  The committed action-tape characterization passed without a fixture delta.

  17 failures from the existing codec export mismatch under Node 22.
- The existing Rust test suites passed (two pursuit tests; A* currently
  defines no tests).
- Real-process checks sent a full-size grid generated by the JavaScript
  implementation through an isolated orchestrator and the Python adapter to
  the actual Rust binaries. Normal startup, late A*, and mid-run attachment
  each produced a 101-point trajectory and three stamped commands with
  increasing sequences. The later-start checks used a loopback Zenoh router
  in the test observer because direct peer discovery was intermittent.
- An actual browser page was not exercised: browser automation could not
  reliably attach to a simulator test tab. Kernel integration is covered by
  the focused tests above. This is not vehicle-control or hardware acceptance.

Native default discovery must work between the adapter and consumers. A
working local Zenoh router can provide connectivity where peer discovery is
unreliable; the adapter does not add a transport fallback or restart service.
